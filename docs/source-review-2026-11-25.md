## API facts

- client.py _send posts to f'{base_url}/{service}/json/{method}' using catalog display names; the catalog has no url_path field, so Configuration, LocalConfiguration and NotifierManager (66 methods) go to paths the OpenAPI spec names Config, LocalConfig and Notifier.
- client.py _parse never reads response headers: no CustomError, no x-amzn-RequestId, no Retry-After handling.
- client.py _parse turns a non-JSON 2xx body into {'_non_json_body': excerpt up to 2000 chars}; tests/test_client.py line 124 asserts that behavior.
- staging.py WriteStager.execute returns status 'committed' and audits commit_done whenever client.call does not raise; any SnapStreamError (including timeouts) returns the note 'The token is spent. Stage again to retry.'
- authTicket is stripped twice: catalog.coerce_params drops it with a note, and client.prepare_body runs strip_auth_ticket (case-insensitive) before every send, so the demo build's required "authTicket": {} for ClipFile cannot be sent today.
- 19 catalog methods carry the note 'Permission requirement depends on the input properties'; AiClipDesigner, DesignExistingClip and UpdateDesign do not, and have perms [] and features [].
- catalog.py _coerce_one passes complex and enum types through unchanged; api_catalog.json has no types or schemas section.
- Settings.timeout_seconds defaults to 30.0 s, above the 29 s gateway limit; max_concurrency 4 is the only throttle for reads; writes are spaced 5 s apart.
- server.py RECORDING_SEARCH_TYPES is {captions:4, program_info:2, all:255} and GUIDE_SEARCH_TYPES is {all:255}; per the spec, 2 is Title only, ProgramData is 58, Default is 254.
- The catalog has 461 methods (246 read, 159 write, 56 blocked) built from SnapStreamAPI.html; no LiveFeed methods are present. FileAccess Exists and GetLength are read, the other 4 FileAccess methods are blocked.
- 128 catalog read methods have perms exactly ['ValidTicket'], including Library/GetTranscript and GetSmartChapters, which the study and playbook say skip folder permissions.
- formatting.SECRET_FIELD_RE masks keys containing token or secret, so AccessToken and AccessSecret objects are replaced whole; the Twitter and Slack account getters are blocked in access_overrides.json.
